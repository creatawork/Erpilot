# Erpilot 项目展示站设计

- 日期：2026-10-09
- 状态：设计已获用户确认，待书面评审；未实施
- 目标受众：求职面试官及希望了解项目的技术读者
- 访问范围：公开展示（用户已确认）

## 1. 目标与成功标准

把 Erpilot 的工程目标、审批边界、已完成能力与验证证据，整理成一个可快速浏览的中文优先作品集页面。访客应能在短时间内理解产品隐喻“动账动货前先请示”、看到审批链路如何工作，并分辨哪些能力已经实现、哪些仍是计划。

成功标准：

1. 页面从问题与产品定位开始，逐步说明交互、工程设计、验证证据和下一阶段方向。
2. 已实现和规划中的内容有清晰区别；项目报告的范围与日期可追溯，不把局部验证扩写成整体结论。
3. 审批演示可以交互，但明确标注为本地模拟，不调用真实 ERP/API、不写入业务数据。
4. 页面在桌面和移动视口均易读、可键盘操作，并遵守基本语义与可访问性要求。
5. 公开发布的源码与资源不含 `.env`、密钥、私有 trace、业务数据库或未经核对的个人信息。

## 2. 现状与内容依据

仓库 README 将项目定位为运行在商品、库存和订单 mini-ERP 上的 approval-aware ERP agent，工具层使用 FastMCP，前端支持流式对话、工具时间线和审批卡片。当前运行时采用 LangGraph 与 PostgreSQL checkpoint；业务数据和 API RunStore 仍为 SQLite。只读工具自动执行，写操作须经过审批。

内容以仓库现有 README、项目计划、前端交互和验收记录为依据。已知证据包括：2026-10-07 基线验收报告、2026-10-08 隔离 PostgreSQL 崩溃恢复报告（R01–R06 进程矩阵 19/19；R07–R10 由确定性组件测试覆盖）。写稿和实施时需再次打开报告核对表述与链接。

RAG 政策问答、多模型横向对比、成功率/成本曲线、公开安全 demo 与档案页属于下一阶段计划，不能描述成已实现或已部署。真实模型评测有波动，不能用定点报告拼成完整基线。页面不承诺身份认证、多租户或生产级 ERP 权限，因为仓库将这些列为范围外或后续事项。

## 3. 方案与取舍

选择一页式、分章节的项目案例站，并在案例中嵌入小型模拟审批演示。

- 简短项目介绍页开发轻、浏览快，但承载不了项目的审批机制和验证证据。
- 完整案例叙述能交代问题、设计取舍、实现状态和证据，适合作品集主体。
- 全屏交互演示吸引人，但容易遮住工程脉络，也可能让访客误以为站点连接了真实 ERP。

因此以案例叙述为主，演示只解释核心流程，不引入账户、持久化、外部集成或新的产品功能。

## 4. 页面结构与体验

1. **首页定位**：主标题“动账之前，先请示”，一句话解释 ERPilot；以掌柜与东家的产品隐喻引出风险分级审批。
2. **模拟审批演示**：展示一条查询与一条写操作的对照；用户可批准或拒绝写操作，页面同步显示“已批准并模拟执行”或“已拒绝，未执行”。常驻标签说明这是预置脚本，不连接业务后端。
3. **工程机制**：以紧凑流程图呈现用户请求 → Agent → MCP 工具 → 风险门 → 人工决策 → 工具结果；说明只读、低风险写入和资金相关操作各自的审批边界。
4. **实现与证据**：展示 LangGraph checkpoint、SQLite 业务库/RunStore 的分工，以及评测和恢复记录。每条数字都带报告日期与适用范围，不推断超出证据的稳定性。
5. **路线图**：分成已完成、当前验证/收尾、规划中；只采用仓库中的状态和描述。
6. **下一步**：提供站内章节锚点以及仓库来源入口（仅在核实可公开访问的仓库 URL 后添加）。

视觉方向为克制的编辑式技术档案：浅暖色页面底、深墨色文字、单一暖红/铜色强调、等宽小标签与清晰排版。避免重复的渐变卡片、虚构指标、客户评价和装饰性动画。交互以审批选择、章节导航与复制链接为限；支持 reduced-motion。

## 5. 内容真实性与安全

- 所有状态、日期、数字、技术边界以仓库或验收报告为准；实施时检查事实与文案链接。
- 模拟结果以“演示数据”呈现，批准按钮不会接触外部服务。
- 仅打包网站必需的静态页面、样式和演示脚本；不复制完整仓库、原始评测 trace、数据库、环境文件或凭据。
- Site 发布范围为 public，与项目 API 是否可公开访问无关；网站不提供 ERP/API 的代理入口。
- 不加入未经用户提供或核实的作者联系方式、头像、公司或招聘声明。

## 6. 实施边界

- Site 通过 Sites 插件托管，使用 buildless 静态 HTML/CSS/JavaScript；无需安装网站框架或连接已有 ERP API。
- 在仓库当前未提交改动之外建立独立工作区，避免覆盖现有更改。站点源码与发布包仅包含批准后的展示内容。
- 创建前检查 Site manifest；若已有项目 ID 则复用，否则仅注册一次。Site 标识只接受 Sites 返回值。
- 建站后设置 public 访问，打包与保存来源版本，再部署该已保存版本；记录部署成功状态与 URL。
- 对浏览器显示、窄屏布局、键盘操作和实际部署页作适当核对；不执行真实模型评测。

## 7. 明确不做

不重构 `apps/web` 或后端，不部署真实 ERP API，不实现登录/写入/API 代理，不承诺多租户安全；不把规划中功能提前展示为当前能力；不添加博客 CMS、数据库、定时内容更新或分析追踪。
