# Erpilot 下一阶段规划：多模型对比 · RAG · 评测叙事 · 可展示收口

- 编制日期：2026-10-08。
- 状态：规划草案，供后续开发交接；本次仅编写文档，未实施下列功能。
- 当前批次清单：[todo.md](todo.md)；长期路线：[启动计划](../docs/agent-project-plan.md)；历史恢复协议：[plan.md](plan.md)。
- 阶段定位：承接已交付的 LangGraph/PostgreSQL HITL 与崩溃恢复对账，把**已有的工程深度转化为求职作品可展示、可讲述的证据**，并补齐 RAG / 多模型两个 JD 硬指标。
- 排序约定：按求职 ROI，优先 JD 硬指标（RAG + 多模型），再做技术叙事与可展示收口。深度优先，不设固定发布日期。

## 1. 为什么是这个方向

从「本项目作为 agent 应用/开发岗求职作品」这个目标倒推，当前瓶颈不是继续加运行时深度（ADR-0010 的多进程租约等属独立后续范围，求职边际收益低），而是三件事：

1. **JD 硬指标缺口**：RAG 未实现、多模型横向对比与路由网关未落地——这两项是国内 agent 岗 JD 的高频必答项。
2. **最有杀伤力的技术叙事未产出**：路线图承诺的「成功率曲线 + 成本优化实录」还没做成一条可讲的曲线；注入防护只有 2 条观察，缺「攻击面 + 防护前后对照」。
3. **作品不可被看见**：无 Dockerfile、无可公开访问的 demo、无档案页/演示视频——招聘方难以在短时间内看出已有深度。

本阶段先补 (1) 的 RAG + 多模型，这同时为 (2) 的对比/曲线叙事提供数据；(3) 的可展示收口按深度优先原则排在其后，但仍列入本阶段范围。

## 2. 规划依据与事实边界

以下为仓库材料与源码静态核对结果，不代表已重跑测试或真实模型评测。

| 已核对的材料 | 当前事实 | 对规划的影响 |
|---|---|---|
| [技术选型 ADR-0001](../docs/adr/0001-tech-stack.md)、[启动计划 §2](../docs/agent-project-plan.md) | LiteLLM 网关、pgvector、多模型对比在选型里，但均**未实现** | 多模型与 RAG 是「计划内但未落地」，需各写一条实现 ADR |
| `agent_core` LLM client | 经 `AsyncOpenAI`（OpenAI 兼容端点）调 GLM-5.3 Flash；无模型路由层；`agent_core` 不依赖任何业务包 | 多模型切换加在配置/网关层，必须保持 `agent_core` 零业务依赖 |
| `evals` runner | 按 case 跑单模型；报告落 `reports/evals/`，有 scorer 版本、预算熔断、瞬态重试、usage/成本计量 | 多模型对比增加「模型维度」，复用现有计量与判分口径，不改 scorer 版本 |

| 部署 | 仅 `.github/workflows/ci.yml`；无 api/web Dockerfile，无全栈 compose | 可展示 demo 需新增容器化 + 安全演示模式 |
| `docs/articles/` | 仅 1 篇（手写 loop）+ 撰写规则 | 系列文章需补 HITL / 崩溃恢复 / 评测三篇 |

## 3. 范围与优先级

**P0（本阶段必做）：** 多模型配置/网关层 + 跨模型横向对比；RAG 单场景（政策问答）含检索链与评测；评测迭代曲线与成本实录；注入防护攻击面与前后对照。

**P1（收口）：** api/web 容器化 + 可公开访问的安全演示 demo + 档案页/演示视频；系列文章补齐；三方向面试叙事卡。

**本阶段不做：** 多 agent 拆分、批量审批产品化、登录/多租户的生产级权限体系（认证作为「对外部署」前置可做最小版，但不做完整 RBAC）、ADR-0010 的多进程执行权/自动业务补偿、模型微调。RAG 严格限定「政策问答」单场景（启动计划 §4 冻结），不扩成通用知识库。

保持 20 个模型可见工具的既定口径；RAG 以**只读检索工具**形式接入现有 loop，不向模型新增业务写能力。`agent_core` 继续不依赖 `erp_store`。

## 5. 各批次设计建议（含待决 ADR）

### 5.1 批次 1 · 多模型网关与横向对比

- **选型待决（ADR）：** LiteLLM 网关 vs 直接用多组 OpenAI 兼容 `base_url`/`key` 的 env 配置。DeepSeek、Qwen(百炼) 均提供 OpenAI 兼容端点，若只需「切换 + 对比」，多端点 env 配置是更省依赖的方案；若要「自动降级/路由」能力则 LiteLLM 更合适。默认取轻量方案，除非降级/路由成为明确需求——结论写入新 ADR。
- 模型配置层加在 `agent_core` 之外或作为其可注入参数，保持 `agent_core` 零业务依赖；mock 单测覆盖切换路径，不烧 token。
- `evals` runner 增加「模型维度」：同一 case 集跨模型跑，报告记录 model、调用次数、实际 usage、估算成本、延迟、重试次数；判分口径与 scorer 版本不变。
- 跨模型跑现有基线，保留各自原始报告，输出对照表。真实模型波动与确定性门槛分开报告，不为对比放宽检查。

### 5.2 批次 2 · RAG 单场景（政策问答）

- 新建可复现的政策文档语料（价格政策、折扣规则、退换货政策），确定性生成或固定文件入库，作为检索对象；与业务库分离。
- **存储待决（ADR）：** 复用现有 PostgreSQL 启用 pgvector vs 先用轻量本地向量存储（面试更易讲取舍）。记录分块策略、嵌入模型、Top-K、相似度阈值。
- 以**只读检索工具**（如 `search_policy`）形式接入现有 loop；回答须基于检索片段并给出来源，语料外问题如实拒答，不臆造。
- 评测新增 RAG 子集：命中 grounded 回答、超出语料拒答、引用正确来源、注入片段不改写用户意图；单独统计，不与业务 case 混比。

### 5.3 批次 3 · 评测叙事 + 注入专题

- 聚合脚本：解析 `reports/evals/*.json`，按 scorer 版本/迭代时间产出成功率、成本、延迟曲线（图 + 机器可读汇总）；把一个真实缺陷「发现→归因→修复→复测」完整串成一段可讲的故事。
- 注入专题：在 `inj-01/02` 基础上扩成攻击面清单（间接注入、身份伪装、越权写入、系统提示词泄露、工具结果投毒），每类给防护前后对照与证据。

### 5.4 批次 4 · 可展示收口

- api、web 各自 Dockerfile + 全栈 compose（含 postgres）；**安全演示模式**：脚本化模型或只读 + 临时库审批，禁用真实写入与真实 key，规避泄露。
- 部署到可公开访问环境；VIE 档案页 + 2–3 分钟演示视频（报价 → 审批卡片 → 拒绝 → 崩溃恢复找回）。
- README 顶部补「30 秒看懂」：架构图 + 一句话价值 + demo 链接。

### 5.5 批次 5 · 文章与面试素材

- 补 HITL 审批协议、崩溃恢复对账、评测体系三篇（遵循 `docs/articles/writing-rules.md`：禁虚构、客观口吻、发布前核对）。
- 三个深方向（工具/HITL/评测）各一页「问题 → 方案 → 数字 → 权衡」面试卡。

## 6. 验收与证据要求

每份验收记录包含：代码 revision/源码哈希、场景与判分版本、固定 seed、模型 id/端点、业务或语料前后状态、执行次数、trace 路径、耗时、成本（调用次数/预算/实际 usage/估算/缺失计量）与失败原因。

- 多模型对比：各模型留**各自**原始报告，不拼接成单次虚构结果；真实模型波动与确定性门槛分开陈述。
- RAG：grounded / 拒答 / 引用三类均需正反例；语料外问题臆造答案为零容忍。
- 注入：防护前后对照必须基于真实运行，保留失败样本，不为通过率放宽检查。
- demo：安全演示模式不得使用真实 key 或改动真实业务库；需附可复现的构建与起停命令。

## 7. 验证入口

仓库根目录现有命令（新增能力的命令在各批次任务中给出，实施后才存在）：

- `uv run pytest`
- `uv run ruff check .`
- `uv run python -m evals --budget 0.1 --timeout 30`（真实模型，消耗 token）
- `apps/web`：`npm test`、`npm run build`

测试默认不调用真实模型；真实模型命令消耗 token，预算是估算熔断线，不是账单硬上限。前端 `npm test` 只覆盖协议测试，浏览器/部署路径需另附操作记录。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 多模型端点行为差异（工具调用格式、JSON 严格度） | 判分口径统一；差异作为对比结论如实记录，不为某模型放宽检查 |
| RAG 范围膨胀成通用知识库 | 严守「政策问答」单场景冻结；扩范围走 ADR |
| pgvector/嵌入引入过多依赖 | 优先评估轻量方案；存储选型写 ADR 对比取舍 |
| demo 真实 key/写入泄露 | 安全演示模式强制脚本化/只读 + 临时库；部署前核对无真实凭据入镜 |
| 真实评测受模型波动影响 | 确定性测试与模型行为分开报告，保存失败，不为通过率放宽检查 |
| 在职时间有限 | 深度优先、批次内先交可验收子片段；不承诺固定日期 |
