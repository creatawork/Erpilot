## 启动、恢复与保留

首次试用可按 README 初始化业务库；恢复已有任务时不要再 seed。默认业务库
`data/erp.db`、运行库 `data/runs.db`、trace `traces/*.jsonl` 必须保留并配套备份。
测试/演示均用独立临时业务库与运行库，不改变常用业务库。

```text
uv run --package erpilot-api uvicorn erpilot_api.main:app --reload
```

启用实际 ERP 工具须设 `ERPILOT_TOOLS=mcp`；写工具再设 `ERPILOT_WRITES=1`。
只启动一个 API 执行进程，不启用多 worker。运行记录和事件首版不自动清理。
正常关闭释放租约并保留检查点；硬终止后旧租约最多 30 秒，页面退避重试。
未知结果先核对原 token；查询失败保持待核对，禁止换 token 重新提交。
显式取消禁止未执行写调用，不能撤销已提交的库存、订单或状态变化；再次核对
取消任务仅查真实结果。schema/checkpoint 不兼容则保留原数据并拒绝恢复，
不要改版本号、删除记录或重置库来绕过检查。

## 恢复 API

| 入口 | 行为 |
|---|---|
| POST `/api/runs` | `{message,session_id}` 创建一次任务并立即返回快照 |
| GET `/api/sessions/{session_id}/runs` | 按创建顺序读取任务快照，页面恢复无需重发消息 |
| GET `/api/runs/{run_id}` | 消息、调用、审批、结果、trace、events、last_seq 的一致快照 |
| GET `/api/runs/{run_id}/events?after_seq=N` | 重放 N 之后的事件再订阅；每项含 run_id/seq |
| POST `/api/runs/{run_id}/resume` | 恢复原检查点；执行者已存在时不重复启动 |
| POST `/api/runs/{run_id}/cancel` | 失效未决审批，停止执行并核对不确定结果 |
| POST `/api/chat/approve` | pending_id/approved 加可选 run_id/session_id/expected_version/arguments_fingerprint；旧入口兼容 |
| POST `/api/chat/stream` | 保留旧流入口，订阅断开不终止后台任务 |

审批未知 404、归属/决定/版本冲突 409、过期 410；错误详情含当前 approval
供页面刷新。持久化决定先落盘，再释放内存等待者。同决定重试返回原结果，
相反决定不能覆写。TTL 默认 1800 秒，可由 `ERPILOT_APPROVAL_TTL_SECONDS`
配置；刷新、服务重建及重复提交均不延长原到期时间。
