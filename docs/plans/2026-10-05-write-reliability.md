# 写操作可靠性实施与验收

用户已授权按项目分析中的后续建议顺序实施；在现有 checkout 的
`codex/write-reliability` 分支逐段执行。保持单主管 agent、20 个工具、SQLite、
手写 loop；持久化审批与 LangGraph 迁移是本轮完成后的后续工作。

## 1. 入口及审批生命周期
- [x] CLI/API 从实际工具 risk 决定读/写提示词，并以 HTTP mock 验证真实入口。
- [x] 正常决策、取消、生成器关闭及同轮多个挂起请求全部释放 waiter；
      不因人的等待触发工具超时，不在断连后继续未批准操作。
- [x] 前端处理网络异常、HTTP 异常与 `{ok:false}`；提交期间禁用按钮，失败可重试。
- [x] 回归原有事件协议、拒绝与批准路径，前端构建并验证界面。

## 2. 写评测的执行证据
- [x] 保留每次工具调用参数、返回值及 ok；批准路径不得把业务错误算成功。
- [x] 每条写 case 独立临时库：批准校验准确变更，拒绝校验四张业务表零变更。
- [x] 不要求所有读侧业务错误为失败：错误恢复本身仍是合法行为。
- [x] 用假成功回答、错误参数、重复写入、未变更与拒绝后变更验证判分防线。

## 3. 幂等及并发
- [x] 写工具增加 client_token，事务内存储请求指纹和结果；相同 token/参数
      返回原结果，不同参数返回 idempotency_conflict，不影响已有库数据。
- [x] bridge 为模型未传 token 的写调用生成稳定 token，同次工具执行重试复用。
- [x] SQLite 写事务使用 BEGIN IMMEDIATE 串行化读改写；并发建单、扣库存与
      同 token 请求以独立连接/线程测试；取消回补重放、失败事务整体回滚有测试。
- [x] 未具备可重放契约的通用写工具不自动重试；读工具保留现有重试。

## 4. 回归与展示
- [x] 全仓 pytest / ruff、前端测试与生产构建；CI 加入前端校验。
- [ ] 完整真实模型评测（临时库、有限预算），保留所有失败并单独记录定点复测。
- [x] 报告记录代码版本、评测集、重试、延迟、成本估算及缺失计量；不把
      定点重跑当作完整基线，不掩盖失败尝试成本。
- [x] 更新 README/项目进度/工具卡/标注标准，交付四场景演示脚本与可靠性复盘。

验收重点：批准执行准确、拒绝零变更、重复请求一次生效、并发不超卖。
评测中代码缺陷必须修复；模型行为失败保留证据后归因，不为通过率放宽检查。
