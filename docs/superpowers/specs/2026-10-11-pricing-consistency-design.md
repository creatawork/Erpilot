# B1：报价与建单计价一致设计

日期：2026-10-11。依据：用户同意功能深化建议，并明确要求落地里程碑和开始开发。

## 问题与目标

`ErpRepository.compute_quote` 对数量应用折扣，`ErpMutations.create_order` 直接保存商品原价。这使「按刚才报价下单」在数量到达折扣档时产生金额差异。B1 统一当前条件下的报价和新单计价，作为订单草稿与审批闭环的基础。

## 选择与取舍

使用业务包内共享定价函数，比在查询和写入分别维护折扣公式更容易保持一致。计算内部使用标准库 Decimal，保留现有 float JSON 字段和 SQLite schema，避免把本次工作扩展成历史数据迁移。使用现有先舍入单价再计算行金额的报价口径，并明确 ROUND_HALF_UP。

## 契约

- Python >=3.12；不新增第三方依赖。
- `agent_core` 保持零业务依赖；定价函数只在 `erp_store`。
- 折扣按同 SKU 合并数量命中；10/50/200 件分别 0.98/0.95/0.90，不跨 SKU 累计。
- 折后单价按 Decimal ROUND_HALF_UP 舍入到两位；行金额用舍入后单价乘数量。订单合计保留现有汇总函数，避免更改历史含半分成交价及已有幂等记录的总额。全库金额类型与计价版本迁移单独规划。
- 折后单价舍入后须至少为 0.01 元；不满足时用 `PricingError` 表达，MCP 返回 `invalid_argument`，建单事务返回同码且不留订单、库存扣减或幂等记录。
- 新订单快照价为折后成交价；历史单据和已有幂等记录不重算。
- 建单仍在现有 `BEGIN IMMEDIATE` 事务内完成商品状态、库存检查、快照、扣库存及幂等记录提交。
- 商品不存在、已下架、库存不足的错误契约不变；失败不留部分订单和库存扣减。
- 保持 MCP 工具参数及返回金额字段兼容；保留 `repository.QUOTE_TIERS` 的导入入口。

## 文件职责

`pricing.py` 管理折扣、十进制舍入与行金额。`repository.py` 用共享计算生成报价；`mutations.py` 在取得写锁后按当前商品价格生成成交单价；`models.py` 保留历史汇总行为，按保存的成交单价计算订单总额。政策文档和工具描述说明报价与新单采用同一口径，旧报价并不冻结当前价格。

## 验收

临时 SQLite 的固定商品测试覆盖各折扣门槛两侧、分行合并、跨商品不累计、半分金额舍入、多行合计、取消回补、执行失败回滚、现价变更后历史单与幂等重放保持不变。MCP 集成测试证明真实工具报价和建单金额一致。全仓离线 pytest 与 ruff 均须运行并记录结果。

审查补充：使用真实历史快照与幂等记录（1.005 元、原合计 1.00 元）检验兼容性；使用 0.005 元 × 200 件检验零成交价在单品报价、批量报价和建单上的一致错误契约。政策源变更后默认检索拒绝旧索引，并重建当前语料的真实索引。

## 后续接口边界

B1 不增加草稿持久化、批准版本或价格锁定。B2 对草稿版本、批准内容和执行条件建立契约；B3 用该确定性内容展示业务审批摘要。B1 不允许以模型文字作为价格或金额依据。
